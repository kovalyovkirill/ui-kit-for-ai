# Page Generator — Session Prompt

You are building a React page from a Pixso mockup using a design system.

## Stack
- React + TypeScript + CSS Modules
- UI kit: `@monorepo/ui-kit` (already installed and imported)
- Tokens CSS: already loaded globally via `@monorepo/ui-kit/styles` and `@monorepo/ui-kit/style`

## Available components
Button, ButtonGroup / ButtonGroupItem, Typography, Input, Checkbox, Avatar, Badge

## Reference — read before implementing

**`.ai-kit/*.kit.md`** is the authoritative Pixso → component mapping for this design system. Before writing any code:
1. Read `.ai-kit/kit.json` for the token naming rule.
2. For every Pixso layer you encounter, look up its layer name or variant in the relevant `.ai-kit/<Component>.kit.md` to find the correct component, prop values, and token names.
3. Do not guess prop names or token values — if a layer matches a documented component, use exactly what the contract specifies.

## Rules — follow strictly
1. Use only components from `@monorepo/ui-kit`. No plain HTML for anything a ui-kit component covers.
2. Use `<Typography>` for every text node. Never raw text or bare `<p>/<h1>/<span>`.
3. CSS values: only `var(--token)`. No hardcoded colors, fonts, sizes, radii, or spacing. Use `--spacing-*`, `--radius-*`, `--fontfamily-*`, `--foreground-*`, `--neutrals-*`, `--border-*`, `--accents-*`.
4. If the design needs a pattern not covered by a ui-kit component (card, list item, modal, etc.), create a co-located app-level component in the same folder using the same rules.
5. Output exactly two files per page: `PageName.tsx` and `PageName.module.css`. App-level sub-components get their own `.tsx` + `.module.css` pair in the same folder.
6. All pages are created in `src/pages/`. Example: `src/pages/TaskList/TaskList.tsx` + `src/pages/TaskList/TaskList.module.css`.
7. **The page file only composes — it contains no layout or styling logic.** Extract every visually or semantically distinct region into its own component. A region qualifies when it: has its own background/border/spacing, repeats across the page, or could be understood independently (navigation, a hero banner, a data column, a card). Each extracted component gets its own `.tsx` + `.module.css` pair co-located in the same folder.

## Pixso
Use only `mcp__pixso-desktop__*` tools. Never use any other design MCP tool.
Node GUID = the `item-id` query value of the Pixso URL (`…?item-id=1:2` → `1:2`).

## Workflow
1. Read `.ai-kit/kit.json` and the relevant `.ai-kit/<Component>.kit.md` files.
2. Call `mcp__pixso-desktop__get_screenshot` on the target node for visual reference.
3. Call `mcp__pixso-desktop__design_to_code` (`clientFrameworks: "react"`) on the node. Use its output **as a read-only reference** for layout, spacing, and `var(--token)` values — never save the generated scaffold or follow its post-processing protocol.
4. Map every element to the closest ui-kit component (from the contracts) or a new app-level component. Confirm ambiguous variants with `mcp__pixso-desktop__get_variants`.
5. Implement TSX + CSS Module. No placeholders, no TODOs.

Token naming: Pixso variables use slashes (`neutrals/surface`) — convert every `/` to `-` (`var(--neutrals-surface)`). CSS generated by `design_to_code` already uses hyphens.
