# 0001. Форма создания задачи

## Context

Пользователь создаёт задачу. Внешний вид полностью определён макетом (`figma`),
контракт данных и правила валидации — схемой `CreateTaskRequest` в `spec`.

Ни то, ни другое здесь не дублируется. Ограничения полей (`minLength`, `maxLength`,
`enum`, обязательность) существуют ровно в одном месте — в yaml; токены, отступы и
типографика — ровно в одном месте, в Figma. Этот документ содержит только то, что
не выводится ни из одного из двух источников.

## Binding

| слой макета             | поле схемы    |
|-------------------------|---------------|
| Input «Название»        | `title`       |
| Textarea «Описание»     | `description` |
| ButtonGroup «Преоритет» | `priority`    |

Значения `priority`: Высокий → `high` · Средний → `medium` · Низкий → `low`.

Тексты, не относящиеся к данным и берущиеся из макета как есть: плейсхолдеры
(«Сделать круто!», «Ты всё знаешь») и хинт под описанием («Но это не точно»).
Хинт — подсказка, а не сообщение валидации.

Действия футера:

- «Добавить» — submit `POST /api/tasks/v1/create`; активна, пока форма валидна по схеме.
- «Отмена» — закрыть форму без запроса.

Ошибки `422` раскладываются под поля по `errors[].field`, который совпадает с именем
свойства в `CreateTaskRequest`.

## Confirmation

```bash
npx tsc --noEmit \
  && node .ai-kit/bin/check-tokens.mjs src/pages/CreateTask \
  && node .ai-api/bin/check-form.mjs createTask
```

`check-form` сверяет форму со схемой в обе стороны: каждое `required`-поле схемы
присутствует в разметке, каждый инпут разметки существует в схеме, и ни одно
ограничение не продублировано в JSX мимо схемы.

## Consequences

- Поле «Описание» потребовало компонента `Textarea`, которого в ките не было.
  Он добавлен в `@monorepo/ui-kit` (Figma `1:12424`, контракт
  `.ai-kit/Textarea.kit.md`) — стаб не нужен. Его четыре значения `min-height`
  off-system: в Figma они захардкожены на вариантах, переменной нет.
- `.ai-api/bin/check-form.mjs` и генератор валидации ещё не написаны — секция
  Confirmation описывает целевую проверку, а не существующую.
- Лейблы полей русские, значения `priority` английские: маппинг лейбл → значение
  живёт в коде формы. Добавление значения в `enum` на бэке потребует правки этого ADR.
